# AFRERA / EBDESIGN Completion Constitution

## Execution mode
- Execute Phase 0 through Phase 100 strictly sequentially.
- One active phase at a time. No parallel implementation tracks during this run.
- A phase passes only with actual evidence; no document claim, index entry, route name, or generated report can substitute for working implementation.
- Failed phases stay failed/blocked until repaired and retested. No silent skip.

## Scope
- Preserve all useful concepts, features, workflows, algorithms, data, UI/UX, integrations, images, product material, AI work, mobile/APK work, ERP/SCM/WMS/TMS/EAM/CRM/DMS/PLM/BI/IoT capability, old files, backups, worktrees, NE material, and GitHub history until reconciled.
- Existing concepts are a baseline, not a ceiling. Missing industry-grade requirements must be researched and added where justified.
- No reduction, simplification, replacement, or cleanup may discard capability merely because another implementation looks newer or more organized.

## Source truth
- Read actual files and actual code.
- Existing indexes are navigation aids only; they are not authoritative evidence.
- A backup, archive, worktree, old folder, library, or generated-looking folder may contain a more complete project than the current branch and must be treated as potentially authoritative until content-level comparison disproves it.
- Reconcile feature-by-feature, not folder-by-folder.

## No-delete lock
- No project-related file or directory may be deleted, moved away, pruned, truncated, reset, cleaned, garbage-collected, or overwritten for cleanup before Phase 100.
- Phase 100 must use PowerShell to inspect both EBDESIGN and EBDESIGN-consolidated in depth before any cleanup disposition.
- Exact duplicates may be identified and hashed earlier, but all copies remain preserved until the final disposition gate.

## Quality
- No fake persistence, silent mock, placeholder PASS, swallowed integration error, or unverified production claim.
- Maintain UI -> UX -> route -> API -> controller -> service -> data/event -> rule/algorithm/AI -> workflow -> platform/domain traceability.
- Prefer deterministic rules, algorithms, optimization, simulation and domain engines where they are more reliable than LLMs.
- AI/agent/plugin providers are replaceable specialists behind governed contracts.
- Security, privacy, accessibility, resilience, observability, performance, migration, deployment and rollback are production requirements, not optional polish.

## Completion
Project completion means working industrial behavior with verified domain workflows, canonical data, module contracts, integration, AI/agents, mobile/APK where applicable, testing, security, deployment readiness, evidence and continuous improvement—not merely a large repository or comprehensive documentation.
